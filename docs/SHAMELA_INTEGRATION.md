# ربط المكتبة الشاملة بعَزْو

## القرار
يدعم عَزْو الشاملة كمصدر خارجي عبر Adapter مستقل يعمل من الخادم فقط.

## لماذا Adapter؟
- لا نربط من المتصفح مباشرة.
- لا نكشف API keys.
- نستطيع تغيير طريقة الوصول إذا تغيّرت واجهة الشاملة.
- يمكننا تطبيق سياسة حقوق مختلفة لكل كتاب/طبعة.
- نحتفظ ببيانات المصدر والإحالة حتى لو تغير مزود الاسترجاع.

## الوضع التقني
توجد مكتبات Node.js غير رسمية تتعامل مع Shamela v4 APIs وتذكر أن الوصول يحتاج:
- `SHAMELA_API_KEY`
- endpoint لبيانات master
- endpoint للكتب

طلب مفتاح الوصول يُوجَّه إلى إدارة الشاملة، بحسب توثيق هذه المكتبات، عبر mail@shamela.ws.

## سياسة الحقوق لعَزْو
حتى نحصل على إذن رسمي واضح:
1. لا نعيد توزيع corpus كامل للشاملة.
2. لا ننشر نسخًا كاملة من الكتب.
3. لا نخزن إلا الحد الأدنى اللازم للتشغيل، وإذا أجازته الشروط.
4. نحتفظ ببيانات الكتاب والطبعة والناشر وموضع النص.
5. نعرض مقتطفات قصيرة فقط بحسب الحق الممنوح.
6. نجعل كل كتاب قابلًا للتعطيل إذا كانت حقوقه لا تسمح بالاستخدام.
7. نميّز بين:
   - public domain
   - licensed
   - restricted
   - unknown rights

## نموذج الربط
```text
AZWO Verification
    ↓
Source Router
    ↓
Shamela Adapter (server-side)
    ↓
Book metadata / section lookup / passage lookup
    ↓
Evidence normalizer
    ↓
source_id + book_id + section/page + excerpt
```

## ما نحتاجه من الشاملة قبل التشغيل الكامل
- طريقة رسمية للحصول على API key.
- شروط استخدام API.
- هل يسمح بالتخزين المؤقت؟
- هل يسمح بالفهرسة الدلالية/embeddings؟
- هل يسمح باستخدام المحتوى في منتج وقفي يقدم خدمات مدفوعة للمؤسسات؟
- حدود إظهار النصوص والمقتطفات.
- سياسة تحديث الكتب والإصدارات.

## مبدأ عَزْو
الشاملة ستكون **مصدرًا مهمًا** وليست "مصدر الحقيقة الوحيد".
كل نتيجة يجب أن تحفظ بيانات الطبعة/المصدر وحالة الحقوق.
